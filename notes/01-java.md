# Java 핵심

## 01. JDK, JRE, JVM은 어떻게 다른가요?

> 상태: ⬜ 미학습

### 답변

JVM은 Java 바이트코드를 현재 운영체제와 CPU에서 실행하는 가상 머신입니다. JRE는 JVM과 표준 라이브러리처럼 실행에 필요한 요소를 묶은 환경이고, JDK는 여기에 `javac`, 디버거, 문서화 도구 등 개발 도구를 더한 개발 키트입니다. Java 코드는 공통 바이트코드로 컴파일되고 환경별 JVM이 이를 실행하기 때문에 이식성이 높습니다. 다만 JVM 구현 자체까지 플랫폼과 무관한 것은 아닙니다.

### 핵심 키워드

`바이트코드` · `가상 머신` · `실행 환경` · `개발 도구` · `플랫폼 독립성`

### 꼬리 질문

1. 바이트코드는 기계어와 어떻게 다른가요?
2. JIT 컴파일러는 왜 필요한가요?
3. JVM의 주요 메모리 영역을 설명해 보세요.

## 02. Java 소스 코드가 실행되기까지의 과정을 설명해 주세요.

> 상태: ⬜ 미학습

### 답변

`javac`가 `.java` 소스를 `.class` 바이트코드로 컴파일합니다. JVM이 시작되면 클래스 로더가 필요한 클래스를 로드하고, 검증·준비·심볼 참조 해결을 포함한 링크 과정과 초기화를 수행합니다. 실행 엔진은 우선 바이트코드를 해석하고, 반복해서 실행되는 코드는 JIT 컴파일러가 네이티브 코드로 바꿔 재사용합니다. 실행 중 생성된 객체의 메모리는 JVM과 GC가 관리합니다.

### 핵심 키워드

`javac` · `클래스 로더` · `링크` · `초기화` · `인터프리터` · `JIT`

### 꼬리 질문

1. 클래스 로더 위임 모델은 왜 필요한가요?
2. JIT과 AOT 컴파일의 차이는 무엇인가요?
3. 클래스 초기화는 정확히 언제 발생하나요?

## 03. 객체지향 프로그래밍의 핵심 특징과 장점은 무엇인가요?

> 상태: ⬜ 미학습

### 답변

객체지향은 상태와 행동을 객체에 묶고 객체 사이의 협력으로 시스템을 구성하는 방식입니다. 추상화는 필요한 역할만 드러내고, 캡슐화는 내부 구현의 변경 영향을 줄입니다. 다형성은 같은 인터페이스 뒤에 여러 구현을 교체할 수 있게 하며, 상속은 타입 관계를 확장할 때 사용할 수 있습니다. 단순한 코드 재사용이라면 강한 결합을 만드는 상속보다 인터페이스와 조합을 우선 검토합니다.

### 핵심 키워드

`추상화` · `캡슐화` · `상속` · `다형성` · `역할과 구현` · `조합`

3. SOLID 원칙과 객체지향의 특징은 어떻게 연결되나요?

## 04. `==`, `equals()`, `hashCode()`의 차이를 설명해 주세요.

> 상태: ⬜ 미학습

### 답변

기본형에서 `==`은 값을 비교하지만 참조형에서는 두 변수가 같은 객체를 가리키는지 비교합니다. `equals()`는 도메인 관점의 논리적 동등성을 정의합니다. `HashMap`과 `HashSet`은 먼저 `hashCode()`로 후보 버킷을 찾고 그 안에서 `equals()`로 최종 비교하므로, `equals()`가 같은 객체는 반드시 같은 해시 코드를 반환해야 합니다. 반대로 해시 코드가 같더라도 해시 충돌일 수 있어 두 객체가 동등하다는 뜻은 아닙니다.

### 핵심 키워드

`동일성` · `동등성` · `equals 규약` · `해시 버킷` · `해시 충돌`

### 꼬리 질문

1. `equals()`가 지켜야 하는 규약은 무엇인가요?
2. 해시 충돌은 어떻게 처리되나요?
3. 가변 객체를 `HashMap`의 키로 쓰면 어떤 문제가 생기나요?

## 05. Java의 `String`은 왜 불변 객체인가요?

> 상태: ⬜ 미학습

### 답변

`String`은 생성된 뒤 외부에서 관찰할 수 있는 값이 바뀌지 않는 불변 객체입니다. 문자열 변경 메서드는 기존 값을 수정하지 않고 새 객체를 반환합니다. 불변성 덕분에 문자열 리터럴을 풀에서 안전하게 공유할 수 있고, 여러 스레드가 별도 동기화 없이 읽을 수 있으며, 계산한 해시 값을 재사용하기도 쉽습니다. 반복 연결처럼 변경이 많은 작업에서는 중간 객체 생성을 줄이기 위해 `StringBuilder`를 사용합니다.

### 핵심 키워드

`불변 객체` · `String Pool` · `스레드 안전성` · `해시 캐시` · `StringBuilder`

### 꼬리 질문

1. `String Pool`은 어떤 문제를 해결하나요?
2. `StringBuilder`와 `StringBuffer`는 어떻게 다른가요?
3. 불변 객체를 직접 설계할 때 주의할 점은 무엇인가요?

## 06. Checked Exception과 Unchecked Exception의 차이는 무엇인가요?

> 상태: ⬜ 미학습

### 답변

Checked Exception은 `RuntimeException`을 상속하지 않는 예외로, 컴파일러가 처리하거나 `throws`로 선언했는지 검사합니다. Unchecked Exception은 `RuntimeException` 계열로 컴파일 시 강제 처리가 없으며, 주로 잘못된 상태나 프로그래밍 오류를 표현합니다. 선택 기준은 복구 가능성과 호출자가 의미 있게 대응할 수 있는지입니다. Spring 트랜잭션은 기본적으로 unchecked 예외에서 롤백하므로 checked 예외까지 롤백해야 한다면 예외 정책과 `rollbackFor`를 명시적으로 설계합니다.

### 핵심 키워드

`Throwable 계층` · `컴파일 검사` · `RuntimeException` · `예외 전파` · `rollbackFor`

### 꼬리 질문

1. 비즈니스 예외는 checked와 unchecked 중 무엇으로 설계하겠습니까?
2. 예외를 무조건 잡아서 새 예외로 바꾸면 어떤 문제가 있나요?
3. `@Transactional`의 기본 롤백 규칙은 무엇인가요?
